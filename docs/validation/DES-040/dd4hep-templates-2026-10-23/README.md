# PR94 reusable chamber templates and placement loops

The [review comment](https://github.com/asalzburger/nodd/pull/94#issuecomment-6360225046) requests reusable chamber shapes, regular placement loops and separate smaller shapes around coils. This refactor keeps the DES039/040 Air-envelope PROTOTYPE and its 936 chambers/36 warm coil reservations.

| Representation | Before | After |
|---|---:|---:|
| Detector XML bytes | 583,236 | 28,900 |
| Detector XML lines | 5,639 | 255 |
| Shape definitions | 936 | 22 |
| Chamber placements | 936 | 936 |

The detector XML is 95.05% smaller. The 22 templates comprise 15 barrel and 7 endcap families, including smaller hardware-clearance chambers. The C++ factory instantiates 22 shared Volume and Solid objects, then uses 21 phi orbits with 56 rows to construct every placement. Six multi-position z rows account for 288 placements; other rows retain their actual nonuniform longitudinal locations. This source needs no residual explicit placements; the schema supports them when a recurrence does not match. There is no invented uniform eta grid or repacking.

The [representation comparison](representation-comparison.json) verifies that all original source/entity fields, counts, identifiers, material and toroid inputs are unchanged. Templates retain unrounded source dimensions; family matching residual is at most 1.77636e-15 m. The [expanded XML audit](../../../../tools/muon_dd4hep/templates.py) reconstructs all world vertices independently of native construction; maximum residual is 1.64313e-14 m. The existing native vertex tolerance remains 1e-10 m. Templates use bounding-box midpoints as local origins; the manifest keeps original source origins/bases/vertices plus centring offsets, and the native audit recovers those source frames.

The initial [native geometry report](geometry-validation.json) passes for 936 unique chamber IDs, 22 shared native volumes/solids, all 288 toroid CSG primitives, 25,248 coil occupancy probes, and zero overlaps at the existing 0.00001 mm numerical tolerance. Maximum native world-vertex residual is 1.68520e-14 m. The source's 50 mm physical interface requirement is separate from that numerical overlap tolerance. The [stock overlap log](checkOverlaps.log), [run report](run.json) and [compressed DDSim log](ddsim.log.gz) retain actual execution and file hashes; this initial run explicitly records dirty source. A committed-source replay follows the source freeze.

The requested 1,000-event 20 GeV gamma run persists all events. The [ROOT truth audit](transport-comparison.json), generated by [check_transport.py](check_transport.py), confirms one parentless PDG22 primary per event, the same complete primary-momentum bank and the same event-by-event secondary multiplicities as the prior retained run. The requested DDSim `uniform` option remains flat polar theta/azimuth; no equal-solid-angle coverage or detector-response result is claimed.

All 15 focused tests pass, including direct XML mutations whose hashes are recomputed to test semantic rejection of bad references/counts/phase/pitches/units/vertices/identities. The first C++ build rejected a plain string passed to the Unicode XML child API; explicit `xml::Strng_t` corrected it. Subsequent build and native execution pass. Independent exact-revision assessment is pending the implementation/evidence freeze.
